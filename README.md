# celevent

[![CI](https://github.com/martin473/celevent/actions/workflows/bot.yml/badge.svg?branch=main)](https://github.com/martin473/celevent/actions/workflows/bot.yml)
[![coverage](https://img.shields.io/endpoint?url=https%3A%2F%2Fraw.githubusercontent.com%2Fmartin473%2Fcelevent%2Fbadges%2Fcoverage.json)](https://github.com/martin473/celevent/actions/workflows/bot.yml)

An event-driven system on the AT Protocol that finds Pittsburgh shows across
Bluesky (accounts, searches, and the live Jetstream firehose), venue websites,
City Paper's event guides, and Ticketmaster. An LLM vets each one, and the real
shows are published from
[@pittsburghevents.bsky.social](https://bsky.app/profile/pittsburghevents.bsky.social)
and in a custom feed, **PGH Shows This Week**.

Case study: [sawyersweet.net/celevent](https://www.sawyersweet.net/celevent)

```
 Bluesky accounts ─┐
 searches ─────────┤
 Jetstream (live) ─┼─► normalize ─► prefilter ─► dedupe ─► LLM review ─► publish
 venue sites ──────┤               (no LLM)     (URI +     (batched,     (reposts, own posts,
 City Paper ───────┤                             text +     schema-       custom feed;
 Ticketmaster ─────┘                             event key) constrained   caps, dry-run)
                                                            JSON)
```

## What's in this repo

| Path | What it is |
|---|---|
| [`bot/`](bot/README.md) | **celevent-bot**, the production service: Node.js + Postgres pipeline, OAuth with DPoP, did:web feed generator, `/healthz`, Prometheus `/metrics`, dashboard, webhook alerts. 54 tests run in CI against a real Postgres. |
| `src/` | **calevent**, the original experiment: a no-backend React calendar where events are structured Bluesky posts. |

### Highlights (details in [bot/README.md](bot/README.md))

- **Event-driven ingest** from the Jetstream firehose plus batch sources, with
  cursors checkpointed in Postgres so restarts never miss or double-process posts.
- **LLM review with guardrails:** batched calls return schema-constrained JSON;
  accept rules (confidence, date window, locality) live in tested code, not the
  prompt. Post text and scraped pages are treated as untrusted input.
- **Discovery agent:** a tool-calling agent finds each venue's official account
  and events page; code verifies every claim (live profile, linked site, URL
  loads) before anything is followed or scraped.
- **OAuth 2.0 with DPoP** as a confidential client (PAR, PKCE, private_key_jwt),
  with single-use refresh tokens guarded by a Postgres advisory lock.
- **One event identity across sources** (date + normalized venue + headliner),
  so a show announced by the venue, the band, City Paper, and Ticketmaster is
  shared once.
- **Operated in production:** structured logs, ingest lag (p50/p95),
  post-to-publish latency, health checks, alerts, and a server-rendered dashboard.

## Run the bot

```bash
cd bot
docker compose up -d && cp .env.example .env   # Postgres 16; add your keys to .env
npm install && npm run migrate
npm run run-once && npm run status             # DRY_RUN=1 by default
```

## Tests and CI

```bash
cd bot
TEST_DATABASE_URL=postgres://celevent:celevent@localhost:5432/celevent npm run test:coverage
```

Every push and pull request runs all 54 tests against a Postgres 16 service.
The build fails if any test fails or line coverage of `bot/src` drops below
85%. The coverage badge is generated by that CI run.

## calevent (the original web app)

A federated event calendar with no backend: events live on users' Bluesky
accounts as regular posts with a structured body.

```bash
npm install
npm run dev     # http://localhost:5173, sign in with a Bluesky app password
```

```
📅 #calevent

TITLE: Design Systems Meetup
START: 2026-05-12T18:00:00.000Z
END:   2026-05-12T20:30:00.000Z
CAL:   cal_a3f9b2c188e14d9a

Join us for talks on tokens and theming.
```

- `#calevent` is a real Bluesky facet, so it shows up in hashtag search and the firehose.
- `CAL:` is a stable per-user ID that ties a person's events together without a server.
- The reader walks your following feed (`getTimeline`), parses matching posts,
  and groups them by month; you can filter by a `CAL:` ID or look up one handle.

```
src/
  lib/atproto.js     # auth, post, parse, fetch
  views/             # Login, PostEvent, Reader
  App.jsx, main.jsx, index.css
```

celevent-bot grew out of this idea, extending it from posts in the `#calevent`
format to the messy, free-text way venues, bands, and promoters actually
announce shows.
